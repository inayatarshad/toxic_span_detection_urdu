# URTOX: Dataset & Research Hub

The public research site for **URTOX**, a manually annotated Urdu toxic-span dataset, and the two
manuscripts built on it: **MUTEX** (text) and **MUTEX-M** (text + audio).

The site presents the dataset schema and statistics, the annotation methodology, an interactive
record explorer, the documented Urdu NLP challenges, the model architecture, results from both
papers, publication status, citation formats, and a reproducibility inventory.

- Dataset: <https://huggingface.co/datasets/inayatarshad/URTOX>
- Preprint: <https://arxiv.org/abs/2603.05057>
- Repository: <https://github.com/inayatarshad/toxic_span_detection_urdu>

---

## Where the numbers come from

The site keeps two categories of figure strictly separate, and labels every one of them:

| Category | Source | Where it lives |
|---|---|---|
| Dataset statistics | Recomputed from `URTOX_v2.csv` | `src/data/stats.json`, generated by `scripts/build_data.py` |
| Model results, protocol, future work | Transcribed from the two papers, with the table or section recorded | `src/data/research.js` |

Every statistic block on the page carries a "Source:" line. Where the released CSV and a paper
disagree, such as record count, category breakdown and mean post length, the site shows the CSV figure and
states the paper's figure alongside it rather than silently choosing one.

### Regenerating the dataset figures

```bash
cd urtox-ui
python scripts/build_data.py
```

This reads `../URTOX_v2.csv` and `../urdu_toxic_audio_dataset.csv`, then writes:

- `src/data/stats.json`, aggregate statistics over all 14,337 records (bundled)
- `public/data/sample.json`, a 2,011-record stratified sample for the explorer (fetched on demand)

The sample is drawn with a fixed seed (42), stratified by `sub_label`, and excludes the handful of
records whose `tokens` and `BIO_tags` lengths disagree, since their spans cannot be rendered
accurately. Serving a sample rather than all 14,337 records keeps the page fast; the explorer says
so explicitly and links to the full dataset.

## Running locally

Requires Node 18+ and Python 3.9+ (only for regenerating data).

```bash
cd urtox-ui
npm install
npm start
```

The site runs at <http://localhost:3000>.

### Production build

```bash
npm run build
```

Output lands in `build/`. To preview it:

```bash
npm run serve:build
```

## Deploying

The site is a static build with no server-side requirements.

### Vercel

Import the repository and set:

| Setting | Value |
|---|---|
| Root Directory | `urtox-ui` |
| Framework Preset | Create React App |
| Build Command | `npm run build` |
| Output Directory | `build` |

`vercel.json` already rewrites all routes to `index.html`.

### Any static host

Upload the contents of `build/`. The only requirement is that `/data/sample.json` is served
alongside the app, which happens automatically since it lives in `public/`.

### Optional: the live inference demo

The research hub is self-contained and needs no backend. A separate live span-detection demo is
reachable at `#/demo` and calls the model API. Point it at a running backend with:

```bash
REACT_APP_API_URL=https://your-space-name.hf.space
```

See `.env.example`. If the API is unreachable the demo reports it; the rest of the site is
unaffected.

### Design

- **Palette**: forest `#26342B`, merlot `#3F0B0D`, sand `#E5D9C6`, cream `#F4EEE2`, ivory `#FBF9F4`
- **Type**: Fraunces (serif) for headings, Inter for body and UI, JetBrains Mono for code and
  figures, Noto Nastaliq Urdu for Urdu text
- **Urdu rendering**: the `.urdu` and `.urdu-inline` classes set the Nastaliq family, `dir="rtl"`,
  `unicode-bidi: isolate` and an enlarged line box so Nastaliq descenders do not collide

Charts are hand-rolled SVG and CSS in `src/site/ui.jsx`; no charting library is used. The only
runtime dependencies are React and `lucide-react`.

## Content handling

The dataset contains insults, profanity and hate speech. The site:

- shows a content warning above the explorer and the annotation examples
- blurs records labelled toxic until the reader opts in with a visible toggle
- reproduces annotation examples verbatim but selects milder records for illustration
- presents the toxic-phrase frequency list as corpus description, not as a lexicon to apply

## Accuracy notes

- Both manuscripts were under review when this site was built. Neither is described as published,
  and no DOI is presented because none has been assigned.
- The released CSV has known annotation inconsistencies. 724 records labelled `non_toxic` carry a
  toxic token tag and 2,177 labelled `toxic` carry none. The explorer flags these records and
  offers a filter for them, and the Dataset Overview reports the counts.
- The audio dataset is TTS-synthesised, not recorded speech. The site states this wherever audio
  results appear.
- `requirements-training.txt` in the repository root pins the training environment to the versions
  reported in MUTEX-M section 5. The training notebooks are written for Google Colab and expect a
  mounted Drive folder for the audio clips.
